美术整合计划

当前所有模型都是 BoxGeometry 拼的，全部材质是纯色 Lambert。这份计划把它替换成一套可加载、可复用、可增量替换的资产管线——关键约束是：不能推倒重来，每一步都要保证游戏仍能跑。

§ 01

现状盘点

先说清楚要替换的是什么。当前的视觉全部由代码生成，好处是零加载、零依赖；坏处是所有角色共用一套比例，怪物之间只靠配色区分，玩家很难在余光里认出"这是屠夫还是腐尸"。

类别当前实现数量问题替换优先级
人形角色humanoid() — 12 个 Box + 可选武器组3 职业 + 12 怪 比例雷同，动作只有腿摆和挥臂P0
兽形角色beast() — 躯干 + 4 腿 + 头6 种 狼、猪、蜘蛛外形几乎一样P0
武器Box 刀刃 / Cylinder 杖 / Torus 弓3 类 × 5 品质色 换装只改颜色，看不出形制差异P0
地面InstancedMesh + 逐格随机顶点色4 套配色 纯色块，近看没有质感P1
阻挡物Cone 树 / Dodecahedron 岩 / Cone 尖柱3 样式 剪影单调，密集时糊成一片P1
建筑Box 墙 + Cone 屋顶 + 发光窗6 栋 六栋房子完全同构P1
特效Box 粒子 / Ring 冲击环 / Cylinder 光束8 种 没有软边和渐隐，偏"硬"P1

音频WebAudio 实时合成15 个音效 可用，但缺环境音与音乐P2
一个容易忽略的点：现在换装能立刻反映在角色和纸娃娃上，是因为模型是即时重建的（rebuildPlayer()）。接入 GLB 之后必须保持这个能力——所以骨架和装备件必须分离，不能烘成一整个网格。
§ 02

管线

两条并行的生产路径：角色和道具走建模路径（Blender → glTF），贴图和图标走生成路径（ComfyUI → 后处理 → 图集）。中间由一个资产清单文件把两边对齐，运行时只认清单不认来源。

§ 03

代码接入点

整个替换只需要动三处：一个新的注册表、一个新的角色工厂、一层动画适配。其余业务代码（AI、战斗、寻路）完全不感知模型来源。

1 · 资产注册表

const AssetRegistry = {
  manifest: null, cache: new Map(), loader: new THREE.GLTFLoader(),

  async boot() {
    this.manifest = await fetch('assets/assets.json').then(r => r.json());
  },

  // 关键：拿不到就返回 null，让调用方回落到程序化几何体
  async load(id) {
    if (this.cache.has(id)) return this.cache.get(id);
    const entry = this.manifest?.[id];
    if (!entry) return null;
    try {
      const gltf = await this.loader.loadAsync('assets/' + entry.path);
      const rec = { scene: gltf.scene, clips: gltf.animations, meta: entry };
      this.cache.set(id, rec);
      return rec;
    } catch (e) { console.warn('[asset] 缺失', id, e); return null; }
  },

  instance(id) {
    const rec = this.cache.get(id);
    if (!rec) return null;
    const g = THREE.SkeletonUtils.clone(rec.scene);   // 带骨骼的必须用这个
    g.scale.setScalar(rec.meta.scale ?? 1);
    return { group: g, clips: rec.clips, meta: rec.meta };
  }
};

2 · 角色工厂（替换 humanoid / beast 的调用点）

// 现在：const m = (t.form==="beast") ? beast(opt) : humanoid(opt);
// 之后：同一个入口，内部决定用资产还是几何体

function makeActor(kind, opt) {
  const inst = AssetRegistry.instance(kind);          // kind: "mob_wolf" / "char_mage" ...
  if (!inst) return opt.form === "beast" ? beast(opt) : humanoid(opt);

  const mixer = new THREE.AnimationMixer(inst.group);
  const clip = n => inst.clips.find(c => c.name === n);
  const actions = {};
  ['idle','run','attack','die'].forEach(n => {
    const c = clip(n); if (c) actions[n] = mixer.clipAction(c);
  });

  // 对外暴露与现有结构相同的字段，业务代码零改动
  return {
    group: inst.group, mixer, actions, rigged: true,
    torso: inst.group.getObjectByName('torso') || inst.group,
    attach: { hand_r: inst.group.getObjectByName('hand_r'),
              head:   inst.group.getObjectByName('head') }
  };
}

3 · 动画适配（改 animateBody 一处）

function animateBody(m, walkPhase, atk, dt) {
  if (m.rigged) {
    const want = atk > 0 ? 'attack' : (Math.abs(walkPhase % 6.28) > .01 ? 'run' : 'idle');
    if (m.cur !== want && m.actions[want]) {
      m.actions[m.cur]?.fadeOut(.15);
      m.actions[want].reset().fadeIn(.15).play();
      m.cur = want;
    }
    m.mixer.update(dt);
    return;
  }
  /* …… 现有的 Box 关节摆动逻辑原样保留 …… */
}
这样切换的好处：任意时刻只要 assets.json 里少了哪一项，那一项自动退回方块模型，其余照常显示。可以一个怪一个怪地替换，不需要"美术全部就位再合并"。

§ 04

分期

四期，每期结束游戏都处于可玩状态。前两期是"看得见收益最大"的部分：玩家自己的角色和最常见的怪。

第一期
骨架

管线打通 + 三个职业

先只做玩家能看到自己的那部分：三套职业骨架、四段基础动画、四把起手武器。这一期真正的产出是管线本身——把 GLTFLoader、SkeletonUtils、AnimationMixer、回落逻辑、进度条全部接完，之后每加一个怪只是往清单里加一行。

3 骨架12 动画剪辑4 武器 assets.json v1加载屏纸娃娃改用同一实例
第二期
怪物

12 种普通怪 + 4 首领

按出现频率排序替换：狼、劫掠者、骷髅、腐尸最先（占总遭遇量的六成以上）。四足与人形各复用一套骨骼命名，动画剪辑跨怪共享，只换网格与贴图。首领各自加一段专属技能动画（跃击 / 骨刺新星 / 召唤）。

12 普通怪4 首领2 套共享骨骼 受击闪白改为材质 emissive死亡改用 die 剪辑
第三期
场景

地面贴图 · 阻挡物 · 建筑

地面从纯色改为可平铺贴图 + 逐格 UV 偏移与色调抖动（保留现有 InstancedMesh，不增加 draw call）。树/岩/尖柱各出 3 个变体打散剪影。石桥镇六栋房子换成 3 种户型 × 2 种旧化程度，并给窗口加一张自发光贴图。

4 套地面9 个阻挡变体6 栋建筑 天空盒 4 张UV 抖动着色器
第四期
质感

UI 图集 · 特效 · 音景

Emoji 全部换成手绘图标图集（技能 18 + 物品 40 + 状态 12），风格统一为铜刻线稿。粒子换成软边贴图 Sprite，冲击环换成带渐变遮罩的着色器。音频加入四段环境床声与两段战斗音乐，用 WebAudio 现有节点做交叉淡入。

风格基准

低多边形 + 手绘贴图

不做 PBR 全套。俯视 3/4 且角色小，法线和粗糙度收益很低，成本却翻倍。用 diffuse + 少量 emissive 就够，材质仍是 Lambert/Standard 的低配组合。

配色纪律

沿用现有区域色板

四张地面图的 fog / floor / sun 色值已经调过一轮，贴图要向这套色板靠，不要各画各的。品质色（白蓝黄橙紫）只作用于材质参数，不进贴图。

验收标准

剪影可辨

每个怪替换后做一次"纯黑剪影测试"：截图去色填黑，三米外能否分辨是哪一种。分不出就重做体型，不靠贴图补救。

§ 06

风险与对策

风险影响对策
首屏体积膨胀，浏览器直开优势消失高硬性预算 8 MB；超预算时优先砍首领贴图分辨率，其次砍变体数量
换装系统与烘焙模型冲突高骨架与装备件分离，挂点命名先定死；导出前用一个校验脚本检查挂点是否齐全
SkinnedMesh 同屏数量导致掉帧中16 米外的怪切换到低模/停用 mixer；同类怪共享 mixer 时间轴做批量更新
资产与代码不同步（改名、漏导）中assets.json 作唯一契约 + 启动时校验清单完整性，缺失只警告不报错
美术产能不足，管线空转中生成路径先行：地面、图标、特效贴图可脚本批量产出，先把"面"铺满再补"点"
风格漂移（不同批次不一致）低先定 3 张参考图（角色 / 怪物 / 场景）作为唯一风格锚点，每批新资产与之并排比对
